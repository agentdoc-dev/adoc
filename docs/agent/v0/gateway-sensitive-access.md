# Gateway-reported sensitive access

The MCP gateway records `adoc.sensitive_access.v1` at the authenticated Cloud sink before releasing sensitive retrieval output. This event reports a local repository read; it does not attest native managed authorization. The registered repository, human principal, authentication session and gateway session come from native setup. The complete effective local retrieval policy is identified by its digest.

The immutable, closed [v1 schema](schema/adoc.sensitive_access.v1.schema.json) covers search, why, graph, stale, contradictions and impacted-by. Subjects carry their real Object ID, original content hash and direct internal or restricted classification. Subjects are sorted and distinct; at most 1000 subjects and 1 MiB of UTF-8 event bytes are admitted. A positive JavaScript-safe sequence orders a gateway session. No source text, query, path or credential belongs in the event. Schema validation grants no authority.

Core collects subjects from the same projected immutable graph used to prepare the response. Returned objects, copied lifecycle/evidence metadata, surviving typed references and emitted graph/signal carriers contribute subjects. Scanned nonhits do not. Prose keeps its prose identity; only real referenced Knowledge Objects become audit subjects. A displayed record can inherit a stricter classification from a contributor, while the event preserves each contributor's direct classification. An additional Sensitive text block identifies the highest exposed classification without widening existing response envelopes.

Local readers share authored scalar projection with the managed reader. Required hidden body becomes empty, hidden optional fields disappear, and authorized siblings survive. Unsupported protected dedicated members fail closed. Removed content loses reference and lifecycle contributions before indexing. Projection preserves original content hashes and canonical artifacts, and filtered embedding composition must match before a retained vector is used. Managed declassification authority stays in the native managed path.

Every outbound event attempt, including acknowledgement-loss retry, requires fresh native audit-metadata egress preflight. The gateway checks the immutable session binding and matching recording receipt before output. Recording failure is `retrieval.audit_sink_unavailable`. Connected recording is this slice's boundary; durable disconnected delivery is a later slice. Ordinary nonsensitive output and local CLI audit exemption remain unchanged. Managed `adoc.sensitive_access.v0` retains its separate exact contract.
