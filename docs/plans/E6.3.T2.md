## Journal framing and state transition

Implement private `crates/adoc-mcp/src/gateway_spool.rs`, wired only from gateway audit. Reuse serde closed-object decoding and core `validate_gateway_sensitive_access`, `to_canonical_json`, `content_digest`; add only narrow immutable event identity/binding getters in the core domain type if needed, not generic JSON scanning or a second event validator.

Journal is UTF-8 newline-delimited compact JSON, **every record including last ends LF**, with these closed tagged records:

```text
header: {kind:"header",format_version:1,root:<canonical UTF-8 path>,cloud_origin,
         workspace_id,repository_id,local_policy_digest,setup_request_id}
binding: {kind:"binding",gateway_session_id,principal_id,auth_session_id}
event: {kind:"event",event_bytes:<exact canonical v1 string>,event_digest}
ack: {kind:"ack",gateway_session_id,event_id,event_digest,sequence}
```

Header is first/exactly once. Header-owned coordinates apply to each binding; binding records contain no transmission permit. Setup request ID is created and durably stored before any ordinary setup request. Replaying the same setup ID under a fresh login produces a new current-auth-session binding natively; append a new binding only when not already present. The root/repo/origin/policy context cannot silently change inside a journal; mismatch refuses and preserves it. This is intentional minimal scope, not automatic rekey/rotation.

Validate the header, every binding, event and ack in order. Event parser preserves original bytes, proves canonical equality and digest, validates exact header/binding coordinates, globally unique event ID, and contiguous positive sequence **per gateway session**. Bindings must be canonical and unique, with one authenticated principal across this journal. Ack references an existing unacknowledged event and exact fields; duplicate/mismatched/out-of-order acknowledgements are corruption. Drain events in journal order; each session's native order remains contiguous. Acknowledged bytes stay in place. Sequence is allocated from durable event history, never the ack cursor. Parse lines incrementally with an 8 MiB record limit (escaped JSON string framing comfortably covers the existing 1 MiB event bound); no whole-file buffering. A missing LF, empty existing file, unexpected record, malformed/duplicate fields, excessive length, mismatch or unsupported version refuses as corruption. No tail truncation or quiet reset.

For a new sensitive transaction, load current token and obtain successful current ordinary setup first; bind current principal/session. Allocate/build the event from the current `ReadAccess`, append and `sync_all` **before sending or returning pending**. Then fresh historical-session transmission preflight and exact-byte POST. On a validated receipt, append exact ack and sync before recorded success. Failed append/sync refuses output even if the remote event was admitted; retry remains deduplicable. Cloud acknowledgement lost after commit yields durable pending; replay uses same ID/bytes/sequence. Both delivery policies persist before POST; synchronous returns refusal rather than pending when recording is unavailable. No rollback/deletion of those attempted events.

Fresh preflight failure/denial, 401/403, 400/409 identity/shape conflicts, malformed preflight, invalid receipt, or unknown authority => refusal. A valid fresh preflight followed by a recording POST network/timeout/5xx/ambiguous acknowledgement failure is only a pending candidate. Immediately before releasing pending, reload the current token and perform another ordinary current-session setup preflight; require the exact same current result binding plus current read/egress success. Unknown/denied authority, binding/session change or malformed response refuses and retains the journal event. Only after this post-failure authority check may spool mode return pending; synchronous still refuses. Root maps native 40001 egress-digest drift to HTTP409 `retrieval.audit_sink_unavailable`, so it is never classified as a generic503 recording outage. No event metadata is transmitted following failed preflight. A malformed receipt is not trusted as an acknowledgement and its bytes are never exposed; retain the event and refuse (stronger than declaring recording). Per-call authority is evaluated immediately before each transmission; it is not a lease across the network gap. Root/native preserves the second admission-time check. Do not fall back to pending after a permission-denied response merely because an earlier preflight passed.
